# Run 9 vs run 8 vs run 7 — same test set (`dataset-run9`), home GPU (RTX 5070) (2026-11-12)

All Q4_K_M, an internal GPU eval script on `data/dataset-run9/test.jsonl` (holdout
ubuntu24; step 2, 2,411 rows). Same backend for all three. Reports
`data/eval-run{9,8,7}-on-run9-report.json`, wrong answers
`data/errors-run{9,8,7}-on-run9.jsonl`. Model run 9: `models/run-20261111220554/`.

working Mozilla / Chrome / VS Code one: 22 Debian samples in train, 8 Ubuntu in
test, F-020) + the `other` rows of the two healthy controls, lost since runs 4
and 8 (F-021).

The "repairs" group of the report also holds the `other` rows of the healthy
controls, so the last two rows are counted from the error files.

**Run 9 fixes F-020**: right file on every broken-source row, with or without a
third-party source next to it (run 8: `mozilla.list` or `vscode.list` in 72/84).

**What run 9 gets wrong:**
- 56 `info.what_i_can_do` instead of `noop.no_issue_found` on healthy `other`
  rows (vague complaints, nothing broken; 50 on Ubuntu; 21 in the "healthy"
  group, 35 on control rows). Harmless: the person is told what chirone can do
  instead of "I found no fault". Run 7 does the same (38); run 8 did not (0).
  The healthy-group gap with run 8 (95.6% vs 98.5%) is these 21 rows.
- 9 `apt.wait_for_lock` on healthy PCs where `unattended-upgrades` holds the dpkg
  lock: same in run 8 and run 7, label noise rather than an error.
- 4 `net_wifi_radio_off` on Ubuntu → `net.enable_networking` instead of
  `net.wifi_radio_on` (run 7 and run 8: 0). Verification would fail and the
  person would be told so, no damage; it is the only real repair regression.
- Actions: `web.search` 56.8% exact as in run 8 (paraphrased queries, see the
  2026-11-08 note: exact is too strict for queries).

Run 7's extra healthy misses compared with run 9: 9 `apt.dpkg_configure` and
3 `disk.apt_clean` on healthy PCs, fixes that do change the system.

**Independent of the model:** since d724bd6 `apt.disable_source` needs a host of
the file in an `apt_update` error line, so run 8's wrong-file answers would be
stopped at the precondition ("nothing to disable") instead of disabling
Mozilla's source; the broken source would stay, though.

**Choice:** run 9. Same safety as run 8 on healthy PCs (9 vs 10 changing fixes),
run 7's repairs minus 4 Wi-Fi rows, F-020 gone. Open points: the Wi-Fi rows and
`noop` vs `info.what_i_can_do` on vague complaints.
