Run 9 here sees prompts shorter than the ones it was trained on, and scores
the same as on its own test set (95.4% exact both times): the cut probes did not
carry anything it relied on.

**What run 10 gets wrong:**
- 9 `apt.wait_for_lock` on healthy PCs where `unattended-upgrades` holds the lock:
  same rows as run 9, label noise.
- **3 `disk.apt_clean` on a healthy Ubuntu PC** (run 9: 0), all the same snapshot:
  disk 50% used, 4.6 GB of APT cache, complaints "the disk is full". Cleaning
  the APT cache only deletes downloaded packages, so it is harmless and arguably a
  sensible answer, but it is the old shortcut from run 3 coming back on one
  snapshot. Worth watching.
- 2 `net_wifi_radio_off` on Ubuntu → `net.enable_networking` (run 9: 4).
- 38 `info.what_i_can_do` instead of `noop.no_issue_found` on vague complaints.
- Actions: `web.search` 59.5% exact, paraphrased queries as before.

**Choice:** run 10. Same or better on every group, shorter prompts where the old
CPU spent the most time, and the only new miss is a harmless cleanup.
