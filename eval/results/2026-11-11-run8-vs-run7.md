**Run 8's regression (lab notes F-020):** on Ubuntu with a broken source *and*
Mozilla's legitimate `mozilla.list`, 44/52 answers pick the right fix
(`apt.disable_source`) with the **wrong file**, `mozilla.list`. Training never
shows a broken source next to a working third-party one: before run 8 every
non-distro file in a training bundle was the broken one; run 8 added PCs where
a non-distro file is fine but none where both are present. At run time the
precondition only checks that the file exists and that `apt-get update` has
errors, so it would let this through.

Run 8's remaining healthy misses: 12 `apt.wait_for_lock` on healthy PCs where
`unattended-upgrades` holds the dpkg lock (arguably a right answer: label
noise in the healthy bundles), 1 `disk.clear_thumbnails`.

Run 7's healthy misses on this set: 20 `info.what_i_can_do` on Ubuntu `other`
rows (harmless), 12 `apt.wait_for_lock` (as above), 5 `apt.dpkg_configure`,
